# UX Audit Report — Arkanzabel

**Дата:** 30.08.2026  
**Аудитор:** Thindie  
**Версия приложения:** текущая разработка

---

## 1. Обзор приложения

Arkanzabel — Android-клиент для VPN-туннелирования на базе v2ray-engine. Приложение ориентировано на пользователей из России, предоставляющих доступ к заблокированным сервисам через конфигурации VLESS/ShadowSocks.

**Ключевая ценность:** автоматическая загрузка профилей из источников, выбор оптимального профиля с тестированием пинга, настройка per-app прокси.

---

## 2. Архитектура навигации

### 2.1. Структура модулей

```
app/
├── feature/
│   ├── intro/          — Экраны приветствия/интро
│   ├── home/           — Главный экран + выбор профилей
│   │   ├── ui/
│   │   │   ├── select/     — Выбор экрана (HomeSelect)
│   │   │   └── newprofiles/ — Список профилей (NewProfiles)
│   ├── managegate/     — Управление источниками
│   │   ├── gatelist/       — Выбор источника (SelectSource)
│   │   └── storedgates/    — Сохранённые профили
│   │       └── profiles/     — Список сохранённых профилей
│   ├── perapp/         — Per-app прокси
│   └── settings/       — Настройки
```

### 2.2. Паттерн навигации

Используется Router-ориентированная навигация с Route-классами для каждого экрана. Каждый экран имеет:
- `*Route.kt` — определение маршрута
- `*Screen.kt` — UI-композиция
- `*State.kt` — модель состояния
- `*Command.kt` — sealed interface команд
- `*StateSink.kt` — обработка событий и переходов

## 3. Детальный обзор экранов

### 3.1. Intro (Запрос разрешений)

**Файл:** `app/src/main/java/com/thindie/rknzbl/feature/intro/IntroScreenContent.kt`

**Назначение:** Экран запроса разрешений (VPN + POST_NOTIFICATIONS), показывается при первом запуске или при отсутствии разрешений.

> **[РЕМАРКА 2026-08-30]:** В исходной версии аудита описан как «экран приветствия» с «кнопкой перехода к основному интерфейсу». **Это неверно.**
> По факту это **permission flow** с четырьмя стадиями:
> - `Stage.Loading` — ожидание
> - `Stage.SoftRequest` — AlertDialog с кнопками "Not now" / "Understood"
> - `Stage.Rationale` — системный запрос разрешения (VpnService.prepare / POST_NOTIFICATIONS)
> - `Stage.RationaleDismissedOnce` — AlertDialog при отказе: "Continue without" / "Open settings"
>
> Здесь нет «приветственного сообщения» и «кнопки перехода». Это стандартный Android permission flow.

**UX-оценка:**
- ✅ Чёткая последовательность запросов разрешений
- ✅ Обработка отказа с возможностью вернуться в настройки
- ⚠️ Нет объяснения, зачем нужны разрешения (только системные тексты)

### 3.2. Home Select (Главный экран)

**Файл:** `app/src/main/java/com/thindie/rknzbl/feature/home/ui/select/HomeSelectScreen.kt`

**Назначение:** Главный экран приложения — точка входа после интро. Хаб-экран с четырьмя действиями.

**Элементы интерфейса (по коду):**

2. **Кнопка "New"** (`ScreenCommand.New`) — переход на NewProfilesScreen (основной рабочий экран)
3. **Кнопка настроек** (`ScreenCommand.Settings`) — переход к Settings
4. **Кнопка Per-App Proxy** (`ScreenCommand.PerAppProxy`) — запуск per-app flow

> **[РЕМАРКА 2026-08-30]:** В исходной версии аудита ошибочно описаны "заголовок со статусом подключения",
> "кнопка выбора источника" и "статус-индикатор VPN". Ни одно из этих элементов на HomeSelectScreen **не существует**.
> Выбор источника осуществляется внутри NewProfilesScreen (SentenceRow → `ScreenCommand.Choose`), а не с главного экрана.

**UX-оценка:**
- ✅ Чистый минималистичный дизайн, 4 чётких действия
- ⚠️ Экран-хаб без контекста: пользователь не видит ни профилей, ни статуса VPN — только кнопки
- ⚠️ Кнопка "Home" ведёт в Stored Profiles, что семантически запутывает (главный экран → "домой"?)

### 3.3. New Profiles (Список профилей)

**Файл:** `app/src/main/java/com/thindie/rknzbl/feature/home/ui/newprofiles/NewProfilesScreen.kt`

**Назначение:** Отображение загруженных профилей из выбранного источника.

> **[ДИЗАЙН-ВОПРОС 2026-08-30]: Нужен ли пользователю выбор профиля вообще?**
> Приложение само пингует все профили и сортирует их по задержке (`profilePingManager.pingProfiles`)
> — «лучший» профиль алгоритмически определён, пользователь лишь подтверждает выбор.
> Это избыточная когнитивная нагрузка: ментальная модель пользователя — «хочу открыть
> заблокированный сайт», а не «выбрать один из N профилей».
>
> **Вывод:** основную нагрузку выбора можно снять — по умолчанию подключать **первый доступный
> (самый быстрый) профиль** одним нажатием (one-tap connect).
> **НО** список профилей не стоит удалять полностью, а **понизить до вторичного экрана**
> «Сменить сервер / продвинутые»:
> - «за» авто-выбор: задержка уже посчитана, первый = лучший, выбор дублирует работу алгоритма;
> - «против полного удаления»: для VPN под РФ важны **протокол/стелс** (VLESS+Reality против SS
>   при DPI) и, возможно, **регион выхода** — это единственная реальная причина ручного выбора.
>
> **Рекомендация:** primary flow = «Connect» (авто-выбор лучшего доступного), список —
> escape-hatch для ручного перебора. Стандартный паттерн VPN-приложений
> (Proton/Windscribe: «fastest» по умолчанию + ручной список серверов).

**Элементы интерфейса (по коду):**
1. **Кнопка назад** — возврат к Home Select (`ScreenCommand.Back`)
2. **Pull-to-refresh** — перезагрузка списка профилей (`ScreenCommand.Refresh` → повторный fetch + ping)
3. **Заголовок** — "Downloaded profiles" (`home_downloaded_profiles_header`)
4. **FilterToggle** — переключатель "All" / "Available"; "Available" disabled пока нет ping-результатов, при замере показывает `CircularProgressIndicator`
5. **SentenceRow: Источник** — отображает текущий источник (или "Choose source"), tap → `ScreenCommand.Choose` → SelectSourceFlow
6. **SentenceRow: Per-app proxy** — "For all or only selected apps" → `ScreenCommand.OpenPerAppProxy`
7. **Список профилей** — группировка по протоколу (`groupBy { it.protocol }`)
   - Каждый профиль: remarks + port, ping (ms / unreachable), transport label (WebSocket, gRPC, KCP…)
   - Визуальная индикация состояния: Testing / Connected / Failed (border)
   - **Long press — только на ВЫБРАННОМ профиле** → диалог подтверждения "Add to saved" → `ScreenCommand.Save`
8. **Кнопка внизу** — "Fetch profiles" (пусто) / "Pick profile first" (нет выбора) / "Stop service" (подключено); loading при `Start`

> **[РЕМАРКА 2026-08-30]:** В исходной версии аудита long press описан как универсальное
> «сохранение профиля в избранное» для любого элемента списка. По факту: long press активен
> **только на уже выбранном (selected) профиле** и открывает диалог подтверждения, а не сохраняет сразу.
> Это существенно более узкий сценарий, чем описано.

> **[РЕМАРКА 2026-08-30]:** Утверждение «нет пустого состояния» **неверно полностью**.
> В коде есть `if (visible.isEmpty())` → текст "No available profiles" (`home_filter_no_available`).
> Отсутствует только состояние «источник не выбран / профили ещё не загружены» — там показывается
> кнопка "Fetch profiles", что является минимальным CTA, но без иллюстрации.

**Состояния профиля:**
- `ProfileBorderState.Inactive` — не выбран
- `ProfileBorderState.Testing` — тестирование подключения (selected + нет результата)
- `ProfileBorderState.Connected` — успешно подключён (`SpeedTestResult.Ok`)
- `ProfileBorderState.Failed` — ошибка подключения

**UX-оценка:**
- ✅ Хорошая группировка по протоколам со sticky-заголовками
- ✅ Визуальная индикация состояния пинга + сортировка по задержке (быстрые сверху)
- ✅ Pull-to-refresh для обновления списка
- ✅ Есть частичное пустое состояние для фильтра "Available"
- ⚠️ Long press только на selected — очень неочевидный паттерн, пользователь не догадается
- ⚠️ Нет полноценного empty state при первом входе (нет источника / нет профилей)
- ⚠️ Кнопка внизу меняет текст, но не disabled визуально при "Pick profile first" — легко нажать зря

### 3.4. Select Source (Выбор источника)

**Файл:** `app/src/main/java/com/thindie/rknzbl/feature/managegate/gatelist/SelectSourceScreen.kt`

**Назначение:** Выбор источника конфигураций для загрузки профилей.

**Элементы интерфейса (по коду):**
1. **Кнопка назад** — возврат назад (`ScreenCommand.Back`)
2. **Заголовок** — "Select source"
3. **Список источников** (ровно 4 строки, `SelectableRow`):
   - **Blacklist: ShadowSocks** — "source_black_ss_subtitle"
   - **Blacklist: VLESS** — "source_black_vless_subtitle"
   - **Whitelist: CIDR** — "source_white_cidr_subtitle"
   - **Custom** — "source_custom_subtitle"
4. **Состояние выбора** — `selectedSource` подсвечивается
5. **Кнопка "Done"** — подтверждение выбора (`ScreenCommand.Done(selectedSource)`)

> **[РЕМАРКА 2026-08-30, исправлено]:** Надо различать **доменную модель** и **UI**.
> - В доменной модели `SelectSourceFlow.Result` (sealed interface) определено **9 вариантов источников**
>   + `NotSelected`: `FullBlackShadowSocks`, `FullBlackVless`, `MobileBlackVless`, `WhiteListMobile`,
>   `WhiteListMobileV2`, `WhiteListAll`, `WhiteListRussian`, `StoredProfiles`, `CustomSource`.
>   Так что исходное «8 источников» по факту **верно** — все эти варианты в коде есть.
> - **UI** (`SelectSourceScreen`) рендерит только 4 `SelectableRow`: SS / VLESS / CIDR (=`WhiteListAll`) / Custom.
>   Остальные 5 вариантов из sealed-интерфейса в списке источников **не показаны**.
> - `StoredProfiles` — это вариант `Result`, но **не строка выбора** в UI; сохранённые профили открываются
>   отдельным экраном через кнопку «Home» на HomeSelect (`ScreenCommand.Home` → `startStoredProfilesFlow()`),
>   а не из Select Source.
> - Различий WhiteListMobile / WhiteListMobileV2 / WhiteListRussian в UI нет — белый список
>   представлен одной строкой «Whitelist: CIDR» (=`WhiteListAll`).
> - «Custom» виден всегда, а не «только при включении в настройках» (в настройках есть
>   `custom_source_url` и `custom_source_enabled`, но сам пункт списка не скрывается).

## 4. Пользовательский путь (User Flow)

### 4.1. Основной сценарий (First Time User)

```
Intro (запрос разрешений VPN + уведомления)
    ↓
Home Select (хаб: New / Home / Per-App / Settings)
    ↓
[New] → New Profiles (по умолчанию источник MobileBlackVless)
    ↓
[Fetch profiles] → загрузка списка + ping всех профилей
    ↓
[Выбрать профиль] → тестирование (Testing → Connected/Failed)
    ↓
[Start] → VPN подключён
```

> **[РЕМАРКА 2026-08-30]:** Выбор источника — **не** обязательный первый шаг.
> `NewProfilesRoute` стартует с уже заданного по умолчанию источника
> (`MobileBlackVless`, см. `initialState`). Пользователь может сразу нажать
> «Fetch profiles»; смена источника — опциональный шаг через SentenceRow «Источник».

### 4.2. Сценарий с сохранёнными профилями

```
Home Select
    ↓
[Home] → Stored Profiles (FavoriteProfilesFlow)
    ↓
[Выбрать профиль] → тестирование / подключение
    ↓
[Start / Stop] → VPN
```

> **[РЕМАРКА 2026-08-30]:** В исходной версии сценария сохранённые профили описаны
> как **пункт выбора источника** («Выбрать StoredProfiles → Stored Profiles») и как
> результат long-press на экране New Profiles. **Частично неверно.**
> - «Stored» — это вариант `Result` в доменной модели `SelectSourceFlow`, но **не строка**
>   в UI Select Source (там 4 строки: SS / VLESS / CIDR / Custom). Т.е. как источник его
>   выбрать нельзя, хотя технически он присутствует в sealed-интерфейсе.
> - Сохранённые профили открываются **отдельным экраном** через кнопку «Home» на
>   HomeSelect (`ScreenCommand.Home` → `startStoredProfilesFlow()`), а не из Select Source.
> - Сохранение профиля в «избранное» — long press **на уже выбранном** профиле в
>   New Profiles → диалог «Add to saved» → `ScreenCommand.Save` (см. §3.3).

### 4.3. Сценарий настройки Per-App Proxy

```
Home Select
    ↓
[Нажать на Per-app proxy] → PerAppProxyScreen
    ↓
[Выбрать режим] → All / Selected
    ↓
[Если Selected] → [Нажать на поиск] → PerAppSearchScreen
    ↓
[Выбрать приложения] → Возврат в PerAppProxyScreen
```

### 4.4. Сценарий настройки

```
Home Select
    ↓
[Нажать на настройки] → Settings
    ↓
[Настроить параметры] → Сохранение в KeyValueStorage
```

## 5. Выявленные проблемы UX

### 5.1. Критические проблемы

#### 5.1.1. Избыточная нагрузка выбора профиля
**Проблема:** Приложение само пингует все профили и сортирует их по задержке, но всё равно
заставляет пользователя вручную выбирать один из списка. Ментальная модель пользователя —
«хочу открыть сайт», а не «выбрать сервер».
**Влияние:** Каждый запуск требует осмысленного выбора, хотя алгоритм уже знает лучший.
**Рекомендация:** One-tap connect — авто-выбор первого доступного (самого быстрого) профиля;
список понизить до вторичного экрана «Сменить сервер» (см. §3.3, §6.1 п.1).

#### 5.1.2. Непонятная навигация между экранами профилей
**Проблема:** Два экрана с профилями — `NewProfiles` и `StoredProfiles` — логически перекрываются.
**Влияние:** Пользователь путается, где находятся его профили.
**Рекомендация:** Объединить в один экран с табами "Все" / "Избранные".

#### 5.1.3. Long press для сохранения — неочевидный паттерн
**Проблема:** Сохранение профиля в избранное требует long press, что не является стандартным паттерном для Android.
**Влияние:** Пользователи не знают о возможности сохранения.
**Рекомендация:** Добавить кнопку "В избранное" (сердечко) на карточку профиля.

#### 5.1.4. Отсутствие пустых состояний
**Проблема:** Нет экранов «Нет профилей» / «Нет результатов поиска».
**Влияние:** Пользователь видит пустой список и не понимает, что делать.
**Рекомендация:** Добавить иллюстрации и CTA для пустых состояний.

> **[РЕМАРКА 2026-08-30]:** Утверждение частично неверно — в NewProfiles **есть** частичное
> пустое состояние: `if (visible.isEmpty())` → текст «No available profiles»
> (`home_filter_no_available`) при активном фильтре «Available». Отсутствует лишь состояние
> «источник не выбран / профили ещё не загружены» — там показывается кнопка «Fetch profiles»
> (минимальный CTA без иллюстрации). См. также ремарку в §3.3.

### 5.2. Средние проблемы

#### 5.2.1. Нет визуальной обратной связи при загрузке
**Проблема:** При загрузке профилей нет индикатора прогресса.
**Влияние:** Пользователь не знает, идёт ли загрузка.
**Рекомендация:** Добавить shimmer/progress indicator.

#### 5.2.2. Статус подключения неочевиден
**Проблема:** На Home Select нет чёткого индикатора состояния VPN.
**Влияние:** Пользователь не понимает, подключён ли VPN.
**Рекомендация:** Добавить крупный индикатор с анимацией.

#### 5.2.3. Select Source: нет описаний
**Проблема:** Пользователь не понимает разницу между WhiteListMobile и WhiteListMobileV2.
**Влияние:** Случайный выбор неправильного источника.
**Рекомендация:** Добавить модальное окно с описанием при первом выборе.

### 5.3. Низкие проблемы

#### 5.3.1. Too many settings
**Проблема:** 7 секций настроек overwhelming.
**Влияние:** Пользователи не настраивают приложение под себя.
**Рекомендация:** Сгруппировать в "Основные" / "Продвинутые".

#### 5.3.2. Нет поиска по настройкам
**Проблема:** Нельзя быстро найти нужную настройку.
**Влияние:** Тратится время на прокрутку.
**Рекомендация:** Добавить search bar вверху настроек.

## 6. Рекомендации по улучшению

### 6.1. Краткосрочные (1-2 спринта)

1. **One-tap connect: авто-выбор лучшего профиля** *(главный приоритет, см. §3.3)*
   - По умолчанию подключать **первый доступный (самый быстрый)** профиль без ручного выбора
   - Primary CTA на экране = «Connect», а не «Pick profile first»
   - Список профилей понизить до вторичного экрана «Сменить сервер» (escape-hatch для
     ручного перебора по протоколу/региону)
   - **Не удалять** список полностью — для VPN под РФ важны стелс-протокол (VLESS+Reality vs SS)
     и регион выхода

2. **Объединить NewProfiles и StoredProfiles**
   - Добавить табы «Все» / «Избранные» в единый каталог серверов
   - Убрать отдельный экран StoredProfiles **как навигационную единицу**, но сохранить
     его функционал (удаление, локальный/remote-режим хранения) — см. вывод о том, что
     список профилей необходим (§3.3): это единственное место удаления и точка входа
     при `Start with favorite profiles`
   - *Примечание:* при внедрении п.1 объединение становится ещё более оправданным —
     оба списка превращаются в один «каталог серверов» с авто-подключением

3. **Добавить кнопку "В избранное" на карточку профиля**
   - Заменить long press на tap с иконкой сердечка
   - Визуально выделять избранные профили

4. **Добавить пустые состояния**
   - NewProfiles: "Нет профилей. Выберите источник."
   - PerAppSearch: "Нет приложений. Попробуйте другой запрос."

5. **Улучшить индикатор загрузки**
   - Shimmer на карточках при загрузке
   - Progress bar на кнопке "Start"

### 6.2. Среднесрочные (3-4 спринта)

6. **Улучшить Home Select**
   - Крупный индикатор статуса VPN с анимацией
   - Быстрые действия (Start/Stop) прямо на экране

7. **Добавить описания к источникам**
   - Модальное окно с объяснением при первом выборе
   - Tooltips при наведении (если возможно)

8. **Реструктурировать настройки**
   - "Основные" / "Продвинутые" табы
   - Search bar вверху

### 6.3. Долгосрочные (5+ спринтов)

9. **Onboarding flow**
   - Пошаговое руководство для новых пользователей
   - Туториал по основным функциям

10. **Профили пользователей**
   - Сохранение настроек в облаке
   - Синхронизация между устройствами

11. **Аналитика использования**
   - Статистика подключений
   - Рекомендации по оптимизации

## 8. Заключение

Приложение Arkanzabel имеет хорошую техническую базу, но требует улучшений в UX:

**Сильные стороны:**
- Чистый минималистичный дизайн
- Хорошая группировка профилей по протоколам
- Тестирование пинга для выбора оптимального профиля

**Слабые стороны:**
- Избыточная когнитивная нагрузка: пользователь вынужден вручную выбирать профиль, хотя
  приложение само пингует и сортирует их по задержке (см. §3.3, §6.1 п.1)
- Непонятная навигация между экранами профилей
- Нестандартные паттерны взаимодействия (long press)
- Отсутствие пустых состояний и обратной связи
- Overwhelming количество настроек

**Приоритетные улучшения:**
1. **One-tap connect** — авто-выбор лучшего доступного профиля (снять нагрузку выбора)
2. Объединить экраны профилей (New/Stored) в один каталог
3. Заменить long press на кнопку
4. Добавить пустые состояния и визуальную обратную связь

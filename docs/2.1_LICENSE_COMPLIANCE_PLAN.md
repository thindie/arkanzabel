# План 2.1 — Лицензионное соответствие GPLv3 (Open Source Compliance)

Детальный план подготовки публичного APK к требованиям лицензии **GPLv3**
(copyleft). Опирается на `docs/COMPLIANCE.md`, `NOTICE` и текущую структуру
проекта `arkanzabel`.

> Дисклеймер: документ — инженерно-процессное руководство, а не юридическая
> консультация. При публичном распространении APK рекомендуется вовлечь
> юридического советника (см. шапку `COMPLIANCE.md`).

---

## 0. Почему это нужно

`arkanzabel` включает код и нативные библиотеки из экосистемы **v2rayNG**,
лиценцированных под **GPLv3** (`libv2ray` AAR из `AndroidLibXrayLite`, а при
использовании TUN — `hev-socks5-tunnel`). GPLv3 — copyleft: при публичном
распространении объединённого приложения (conveying) возникают обязательства:

1. Предоставить **соответствующий исходный код** GPL-частей (§1, §6).
2. Приложить **текст лицензии** и сохранить все уведомления о ней (§4, §5).
3. Отобразить в UI **«Appropriate Legal Notices»** (§7): copyright, отказ от
   гарантии, право распространения по этой лицензии и способ получения исходного кода.
4. Вести **сводку атрибуции** третьих сторон (`open_source_licenses.html`).

Репозиторий публичный → исходный код уже доступен (обязательство №1 частично
выполнено для кода в репозитории). Остаётся закрыть тексты, уведомления и
атрибацию в самом приложении.

## 2. Что добавляем (deliverables)

### 2.1 `LICENSE` в корень репозитория (GPLv3, полный текст)

- **Путь:** `arkanzabel/LICENSE`
- **Содержимое:** полный текст GNU GPL v3 (из `https://www.gnu.org/licenses/gpl-3.0.txt`).
- **Зачем:** требование §4 («give all recipients a copy of this License»).
- **Формат:** plain text, UTF-8, без изменений текста лицензии.

### 2.2 `NOTICE` / attribution (дополнение к существующему)

- В репозитории уже есть `arkanzabel/NOTICE` (указывает на GPLv3 + v2rayNG +
  `docs/COMPLIANCE.md`).
- **Доработать:** добавить таблицу текущих версий зависимостей (раздел из п. 1.2)
  и пометку, что соответствующий исходник доступен в этом публичном репозитории
  + в разделе «About» приложения.

### 2.3 Запакованный `assets/licenses.html` (сводка атрибуции)

- **Путь:** `app/src/main/assets/licenses.html`
- **Содержимое:** HTML-сводка всех лицензий (GPLv3 для движка + Apache-2.0 для
  зависимостей). **База — готовый `open_source_licenses.html` из v2rayNG**
  (`V2rayNG/app/src/main/assets/open_source_licenses.html`); адаптировать под
  актуальные версии из каталога.
- **Зачем:** источник для в приложении (п. 2.4) и архив артефакта релиза.

### 2.4 Экран «Open source licenses» в приложении + строка в настройках

Новый Compose-экран, который открывается из настроек. Отображает текст
`licenses.html` (через `WebView`) или как обычный прокручиваемый текст — см. п. 5.

- **Пакет:** `com.thindie.rknzbl.feature.settings.ui.licenses`
- **Файлы** (повторяем паттерн `inputurl`):
  - `LicensesRoute.kt` — `HomeFlow.createLicenses()` через `RouteFactory.create(...)`
  - `LicensesState.kt` — `data class LicensesState`
  - `LicensesCommand.kt` — sealed interface (`Back`)
  - `LicensesScreenContent.kt` — Composable + inline preview (по правилам проекта)
- **Строка в настройках:** добавить кликабельную строку в
  `SettingsScreenContent.kt`, ведущую в экран (`go(createLicenses())`).

### 2.5 «Appropriate Legal Notices» (§7)

- В экране лицензий и/или в «About» отобразить:
  - copyright-строку (правообладатель + год);
  - «This program comes with ABSOLUTELY NO WARRANTY; for details type `show w`;»
    аналог и ссылку на полную лицензию;
  - указание, что программа распространяется по GPLv3, и где взять исходник
    (ссылка на репозиторий / раздел «About»).

## 3. Детальная реализация экрана (MVI-паттерн проекта)

Опираемся на существующий рабочий паттерн `inputurl` — минимальные изменения,
максимальная согласованность с кодовой базой.

### 3.1 Маршрут (`LicensesRoute.kt`)

Повторяем структуру `InputUrlRoute.kt`:

```kotlin
package com.thindie.rknzbl.feature.settings.ui.licenses

import com.thindie.engine.core.RouteFactory
import com.thindie.rknzbl.feature.home.HomeFlow

fun HomeFlow.createLicenses() =
  RouteFactory.create(
    initialState = LicensesState(),
    execute = { c: LicensesCommand, s: LicensesState ->
      when (c) {
        LicensesCommand.Back -> { back(); null }
      }
    },
    id = "LicensesRoute",
    routeContent = ::LicensesScreenContent,
  )
```

### 3.2 Состояние и команды

- `LicensesState()` — пустое (или с флагом загрузки HTML).
- `LicensesCommand: sealed interface { data object Back }`.

### 3.3 Контент (`LicensesScreenContent.kt`)

Композиция повторяет стиль `SettingsScreenContent.kt`:

- Обёртка `AppScreen(scope) { ... }`;
- `TopAppBar` со стрелкой назад (`Action(resRef = R.drawable.ic_arrow_back_24)`),
  обработка через `BackHandler { scope.send(LicensesCommand.Back) }`;
- Загрузка контента:
  - **Вариант A (WebView):** `AndroidView { WebView(it) }` → `loadUrl("file:///android_asset/licenses.html")`.
    Плюс: точное форматирование v2rayNG-сводки. Минус: добавляется `WebView`
    (уже есть в AndroidX/системный, новых зависимостей не требует).
  - **Вариант B (plain text):** прочитать `licenses.html`, вырезать теги →
    прокручиваемый `Text` через uikit-компоненты. Плюс: проще, нет WebView;
    Минус: теряется оформление.
- **Решение по умолчанию:** Вариант A (WebView), так как сводка из v2rayNG — это
  HTML с цветами/ссылками; при желании легко переключить на B.
- **Preview** в конце файла (`@Preview`), как требует правило проекта
  («every self-created Compose component must have the preview»).

### 3.4 Строка в настройках

- В `SettingsScreenContent.kt` найти блок отрисовки строк (паттерн
  `.fillMaxWidth().clickable(onClick = onClick).padding(12.dp)`), добавить новую
  строку типа `SentenceRow`/кастомную:
  - заголовок «Open source licenses» (строковый ресурс, п. 4);
  - `onClick = { scope.send(LicensesCommand.OpenLicenses) }`;
- В `ScreenCommand` добавить `data object OpenLicenses`;
- В `SettingsRoute.kt` (`execute`) обработать команду → `go(createLicenses())`.

## 5. Выбор способа отображения текста (WebView vs plain text)

| Критерий | WebView (A) | Plain text (B) |
|----------|-------------|----------------|
| Сохранение оформления v2rayNG | ✅ | ❌ |
| Новые зависимости | нет (системный) | нет |
| Простота / кастинг | средняя | высокая |
| Доступность (accessibility) | хуже | лучше |

Рекомендую **A (WebView)** как ближайший аналог v2rayNG, с возможностью замены
на B без изменения маршрута.

## 8. Риски и замечания

- **Актуальность версий.** Сводку нужно сверить с фактическими версиями из
  `libs.versions.toml`, иначе атрибуция неточна.
- **Локализации.** Строки обязательны для `en` и `ru`; не забыть про
  `locales_config.xml`.
- **hev-socks5-tunnel (см. 2.2).** Если в релизе будет использоваться TUN через
  hev, его лицензию (upstream) тоже нужно добавить в сводку; сейчас `.so` не
  зафиксирован и путь по умолчанию выключен — отдельной работы не требует.
- **Юридическая проверка.** Публичный релиз GPL-приложения — зона повышенной
  ответственности; согласовать финальный текст уведомлений с юристом
  (см. шапку `COMPLIANCE.md`).
- **Не ломать существующее.** Изменения только в фиче `settings` + новые файлы;
  логика VPN/движка не затрагивается.

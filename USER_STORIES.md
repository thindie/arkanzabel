# User Stories — Arkanzabel

**Дата:** 30.08.2026
**На основе:** `UX_AUDIT.md`
**Фокус:** снять нагрузку выбора через one-tap connect; список профилей оставить escape-hatch.

---

## Основная история (one-tap connect)

> **Как** пользователь, который хочет открыть заблокированный сайт,
> **Я хочу**, чтобы приложение сразу подключило лучший доступный профиль одним нажатием,
> **Чтобы** не выбирать сервер вручную каждый раз.

**Критерии приёмки:**
- При входе в NewProfiles автоматически пингуются все профили и выбирается самый быстрый (первый доступный).
- Главная кнопка = «Connect» — подключение без ручного выбора.
- Список профилей доступен как вторичный экран «Сменить сервер» для ручного перебора.

---

## Вторичные истории

### 1. Ручной выбор (escape-hatch)

> **Как** опытный пользователь, я хочу вручную выбрать профиль по протоколу/региону, чтобы обойти DPI или получить нужный выход.

- Экран «Сменить сервер» показывает профили с ping и transport (WebSocket/gRPC/KCP).
- Перебор по протоколу важен для РФ: VLESS+Reality vs SS при блокировках.
- Возможно нужен выбор региона выхода.

### 2. Сохранение в избранное

> **Как** пользователь, я хочу добавлять понравившиеся профили в «избранные» тапом (сердечко), чтобы не искать их заново.

- Заменяет неочевидный long press (см. `UX_AUDIT.md` §5.1.3).
- При `Start with favorite profiles` приложение открывается сразу избранными.

### 3. Empty states

> **Как** пользователь, я хочу понимать, что делать, когда профилей нет, чтобы не гадать.

- «Нет профилей — выберите источник» с кнопкой выбора источника.
- Иллюстрация + CTA вместо пустого списка (см. `UX_AUDIT.md` §5.1.4).

## Заметки по реализации

- **Не трогать домен**: `ConnectionProfileRepository`, `profilePingManager`, `FavoriteProfilesFlow`, `SettingsRepository` — общие для обоих экранов, остаются как есть.
- **Объединение New/Stored** (§6.1 п.2): табы «Все» / «Избранные» в едином каталоге серверов; функционал удаления и режимов хранения сохранить.
